# 架构与规则决策

## 数据流

浏览器 UI → Socket.IO 事件 → 连接绑定的玩家 ID → 原子规则 reducer → 私密字段按玩家过滤 → 房间广播 → React / Three.js 展示。

客户端不提交完整状态，不接受客户端指定身份、骰点、资金或价格。`dispatch` 在 `structuredClone` 副本上应用操作；任何验证失败都丢弃副本。Node 单线程事件循环串行处理房间操作，避免同一资产被两个并行请求同时买入。

状态：大厅 → 对局中（roll → buy 或 manage → auction → manage → 下一玩家）→ 结束。拍卖在全房间暂停移动，股票和银行等操作仍可用。竞拍最高出价占用可用现金。

## 模块

- `shared/types.ts`：协议与领域状态。
- `shared/catalog.ts`：地图、职业、路径拓扑；可独立扩充场景。
- `shared/finance.ts`：现金、负债、净值、估价、租金和信用公式。
- `server/engine.ts`：规则、宏观事件和可复用机器人决策。
- `server/index.ts`：传输、房间生命周期、令牌、断线与持久化。
- `src/Board.tsx`：全部 3D 几何体本地生成，无第三方模型。
- `src/App.tsx`：仅发送动作请求并根据服务器快照显示 UI。

## 对 GDD 未定项的明确解释

1. “回合”在本项目分为个人回合和全体完成一遍的“轮”。30 轮结算；事件、股息按轮；工资按过起点；税和债务利息按个人回合。
2. 货币单位万元，保留两位小数，统一 `money()` 四舍五入。股票股数为正整数。不用真实货币、真实证券接口。
3. 简化股票市场为系统报价成交；无总股本、挂单簿或 51% 控股。本次只有股票投资，控制权列入 V0.2。
4. 市场行情和地产指数有上下限，防止长局无界膨胀。先做闭环，后做平衡。
5. 即时租金记入对方收入，欠款玩家现金可暂时为负。负数表示未弥补的流动性缺口；无法正常结束回合。
6. 重组清算债务时把负现金计入，股票以市价九折抵债，存款全额抵债，残余债务保留 20%。地产进入银行资产拍卖，竞拍款进入系统银行，不重新发给破产玩家。重组是一项替代行动，结束后进入管理阶段。
7. 地产按当前市值计净资产；抵押本金单独扣除，避免双计。股票成本基准随玩家转让按比例延续。
8. 机器人策略以现金安全线、估值折价和资产价值为基础；不读取未来骰子，不做机器学习决策。玩家离线后复用同一策略。
9. 相同净资产时按入场顺序稳定排序，不另设隐藏评分规则；未来可增加并列名次展示。

## 存储

快照采用临时文件写入后 rename；约每 1.5 秒一次，同进程串行写入。保留七天内房间。`DATA_DIR` 可重定向。依赖锁文件已经提交到项目，`data/`、构建和依赖目录不应进入源码管理。

此方案适用于单机开发和朋友局，断电可能损失最近约 1.5 秒操作。生产迁移建议拆分 rooms、players、holdings、properties、trades、transactions、snapshots 表，采用事务和动作幂等 ID，并引入房间 owner/lock，不能把当前多份 Node 实例直接指向同一 JSON 文件。

## 安全边界

- 24 字节随机重连令牌，仅返回创建者及重连本人；仅保存于原标签页的 sessionStorage。
- 连接数据绑定玩家 ID，动作里的 playerId 不决定权限。
- 接口限制每秒 15 条请求、单消息 16 KB；金额有类型、有限性和上下界检查。
- 玩家名和消息限制长度，React 文字转义显示；消息不作为 HTML 渲染。
- 私聊与交易提案只发送给参与双方；棋盘与资产本身为公开信息。
- 本地存档内令牌为明文，需依靠操作系统文件权限。没有密码、账号、安全审计或跨设备登录。
- 公网正式发布前需要 HTTPS、允许来源限制、IP 级速率与房间配额、持久化事务、备份和运维方案。本次没有暴露公网端点。
