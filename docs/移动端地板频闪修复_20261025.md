# 移动端道路 / 中央广场地板频闪修复

## 现象

手机上旋转或缩放棋盘时，主环路面、内街路口和中央广场铺装会出现局部明暗跳变，像“地板在闪”。桌面端偶发但不明显。

## 原因

这是两层问题叠加：

1. **相机深度范围过大**
   棋盘相机此前使用 Three.js 默认的 `near = 0.1`、`far = 2000`，但棋盘主体距离相机只有约 40 个单位，缩放范围也只到 140。深度缓冲的大部分精度被浪费在远处，手机 GPU 的深度精度通常又比桌面更紧，薄薄一层地板叠层就会在相邻像素间来回“赢”深度测试。

2. **地板叠层存在共面**
   - 中央广场浅色步道盒体的底面是 `0.105`，正好等于广场石板的顶面 `0.105`，两层完全共面。
   - 内街路面底座顶面 `0.046` 与深色内衬底面 `0.046` 共面。
   - 内街转角圆柱路面、直线路面、坡道都在 `0.0505`，顶面同为 `0.052`。
   - 停车位、箭头、标线又紧贴这些表面。

共面表面本身就会 z-fighting；相机一移动，深度值在浮点精度边缘来回变化，就表现为频闪。

## 修复

### 1. 收紧相机深度范围

`src/Board.tsx`：

```tsx
camera={{ position: [24, 26, 29], fov: 38, near: 0.5, far: 420 }}
```

`near` 从 0.1 提到 0.5、`far` 从 2000 收到 420，深度精度约提升 24 倍；最远城市半径 220、相机最远 140，`far = 420` 仍覆盖完整远景，`near = 0.5` 也不影响最近 2.3 的检视距离。

### 2. 把共面层真正分开

- 中央广场浅色步道从 `0.112` 抬到 `0.113`，底面 `0.106` 不再贴在石板顶面 `0.105` 上，并加 `polygonOffset`。
- 内街各层按绘制顺序使用不同的 `polygonOffset`：
  - 转角底座 `-1`
  - 深色内衬 `-2`
  - 直线路面 `-3`
  - 转角路面 `-4`
  - 坡道 `-5`
  - 停车位 `-6`
  - 标线 / 虚线 `-7`
  - 箭头 `-8`
- 主环路面也加了轻微 `polygonOffset`，避免和棋盘沥青基座在低精度设备上争夺同一深度层。

`polygonOffset` 只改变深度测试的偏移，不改变几何位置和可见高度，所以棋子、路面和建筑的关系不变。

## 验证

- `npm test`：219 项通过。
- `npm run build`：通过。
- 无头 Chrome 手机视口（390×844，DPR 2.5，触摸模拟）打开单人练习局并滚轮缩放到棋盘特写：页面无异常、无控制台错误，中央广场、主环和内街层次正常。
- 对比截图在 `artifacts/mobile-flicker/`。

> 说明：无头 Chromium 使用桌面 GPU/SwiftShader，不能完全等价于真实手机的 16/24 位深度缓冲。这次修复同时处理了“共面”和“深度范围”两个根因；如果某台手机仍出现，请提供机型/浏览器和录屏，下一步可以再启用 `logarithmicDepthBuffer` 或单独排查阴影贴图。

## 刷新方式
