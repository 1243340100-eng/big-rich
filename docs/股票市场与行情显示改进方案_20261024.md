# 股票市场与行情显示改进方案

> 日期：2026-10-24  
> 状态：P0/P0.5 已完成；P1/P2 已获用户明确批准并实施  
> 本文件保留原始方案及分阶段记录。用户已明确批准同时实施 P1/P2；新版规则与详情实现见《股票规则与详情实施记录_20261024.md》。下文“当前”指实施前状态，“需确认”指原方案阶段。

## 1. 结论

股票系统需要改，但不建议把它做成复杂的模拟炒股软件。

当前最有价值的方向是：

1. **显示层先升级**：把现有迷你折线图做成真正的行情图，并采用中文股市习惯的红涨绿跌。
2. **规则层再做差异化**：让六只股票拥有不同的波动、行业敏感性和股息特征。
3. **给股价一个锚**：从纯随机游走，改成“合理价值 + 随机波动 + 事件冲击 + 均值回归”。
4. **连接城市经营**：让地产、区域发展和股市产生弱关联，而不是两套完全独立的系统。

整体原则：**保留六只股票，不增加做空、期权、融资融券、订单簿等复杂工具；股票是地产主玩法之外的辅助投资，不应喧宾夺主。**

## 2. 实施前实现摘要

### 2.1 当前六只股票

| 股票 | 初始价 | 股息率 | 当前特征 |
| --- | ---: | ---: | --- |
| 星海银行 | 12 | 3% | 金融 |
| 城市地产 | 10 | 2% | 地产 |
| 新能集团 | 15 | 2.5% | 能源 |
| NEO 科技 | 20 | 1% | 科技 |
| 快乐食品 | 8 | 4% | 消费 |
| PIXEL 娱乐 | 9 | 2% | 文旅 |

### 2.2 当前价格机制

- 每完成一整轮，所有股票先进行一次随机波动，再叠加当前经济周期的固定偏置。
- 每 2/3/4 轮触发一次全球事件；事件再对股票价格乘一次行业系数。
- 玩家和 AI 可以随时买卖股票。交易数量会产生价格冲击，并同时影响成交价和之后的市场报价。
- 每 5 轮按持股数量发放一次税后股息。
- 交易有手续费；盈利卖出有 10% 资本利得税。
- 股价被限制在 1–500。

### 2.3 当前界面

- 顶部行情条显示股票名、价格、涨跌幅。
- 股票标签页里每只股票有一张卡片：
  - 名称、行业、价格、涨跌幅
  - 一条 `Spark` 折线/面积图
  - 持有数量、盈亏、均价、市值
  - 买入/卖出按钮
- 当前 `Spark` 只有一条折线、一个面积填充和底部基线：
  - 没有网格
  - 没有昨收基准线
  - 没有最高/最低价
  - 没有最新价圆点
  - 没有“最近 30 轮”标识
  - 没有悬停价格提示
- 当前颜色规则是全局 `.positive` 绿色、`.negative` 红色，偏国际市场习惯。

### 2.4 当前问题

1. **同质化**：六只股票共用同一套随机波动和周期偏置，只有初始价、股息率和少数事件特判不同。
2. **没有估值锚**：纯随机游走可以漂到 1 或 500，30 轮内运气成分很大。
3. **与城市经营脱节**：地产升级、区域发展不会影响对应公司的股价。
4. **事件与周期矛盾**：全球事件随机，但经济周期永远按顺序前进，可能出现“金融危机”发生在“繁荣”周期。
5. **界面信息不足**：折线图像装饰线，交易前也看不到价格冲击、股息倒计时和估值位置。
6. **AI 参与度低**：机器人股票交易很少，市场不够活跃。
7. **事件系数需复核**：实施时确认其他股票实际乘 0.96，银行/地产乘 0.8；0.7 是房价系数。因此原文“额外承压”与代码一致，本项不需要改文案或规则。

## 3. 显示层改动（已确认方向，P0）

### 3.1 不改数据，只升级展示

现有 `Stock.history` 已经保存最近 30 轮价格，`price` 是当前价，`previous` 是上一轮收盘价，足够做迷你行情图。

本阶段不增加服务器字段，不改交易规则，只改前端。

### 3.2 红绿配色

采用中文股市习惯：

- **红色 = 上涨**
- **绿色 = 下跌**
- 同时保留 `▲ / ▼`、`+ / -` 和百分比，不能只靠颜色区分。

建议颜色令牌：

```css
--market-up: #b3563e;
--market-down: #2f7d5b;
--market-grid: rgba(91, 76, 55, 0.14);
--market-baseline: rgba(91, 76, 55, 0.45);
```

深色主题可沿用现有深色卡片中的珊瑚红/薄荷绿，但语义同样保持红涨绿跌。

**关键约束：不要直接改全局 `.positive` / `.negative`。**

股票模块单独使用：

```css
.market-up { ... }
.market-down { ... }
.stock-card .market-up { ... }
.stock-card .market-down { ... }
.market-strip .market-up { ... }
.market-strip .market-down { ... }
```

原因：净资产、现金流、租金等“正向收益”目前使用绿色，如果全局翻转，会把这些内容错误地变成红色。股票模块可以有自己的图例：

> 红涨 · 绿跌 · 最近 30 轮

股票模块内部的“盈亏”建议同样采用红盈绿亏，保持板块内一致；股票模块之外的资产变化仍保持绿正红负。

### 3.3 迷你行情图规格

保留纯 SVG，不引入图表库。

每只股票卡片内：

- 折线：最近 30 轮收盘价 + 当前价端点。
- 区域填充：折线下方低透明度渐变。
- 横向网格：3–4 条浅色线。
- 昨收基准线：在 `previous` 位置画虚线。
- 当前价圆点：折线最右端，带轻微脉冲。
- 最高/最低价：显示当前窗口的高点和低点。
- 横轴：不显示每一轮，只在右下角标注“最近 30 轮”；详情弹窗再显示轮次刻度。
- 悬停：显示某一轮的价格，例如“第 24 轮 · 11.90 万”。
- 折线颜色：
  - 当前价高于 `previous`：红色；
  - 当前价低于 `previous`：绿色；
  - 持平：中性深色。
- 空数据/单点数据：
  - 只有一个价格时画水平线和一个圆点；
  - 不出现 NaN、空 SVG 或断线。

建议的卡片结构：

```text
┌────────────────────────────────────┐
│ 星海银行                     12.00 │
│ 金融 · BANK                ▲ +2.40% │
│ ┌────────────────────────────────┐ │
│ │          ╱╲                    │ │
│ │      ╱╲╱  ╲___●                │ │
│ │ ──── 昨收 11.72 ────────────── │ │
│ └────────────────────────────────┘ │
│ 高 12.20 · 低 10.90 · 最近 30 轮   │
│ 持有 10 股 | 成本 11.20 | +8.0 万  │
│ [买入] [卖出]                      │
└────────────────────────────────────┘
```

### 3.4 顶部行情条

顶部只做紧凑展示，不放迷你折线图：

- 股票名
- 最新价
- `▲ +2.40%` 或 `▼ -1.20%`
- 红涨绿跌
- 悬停显示昨收、最高、最低

六只股票横向空间有限，不要在顶部塞图表，否则会显得拥挤。

### 3.5 股票详情弹窗（P2，可后置）

点击股票卡打开详情：

- 5 / 10 / 30 轮切换
- 更大的折线图
- 横向十字线 + 悬停价格
- 股息、财报、全球事件的标记
- 当前估值位置：偏低 / 合理 / 偏高
- 主要敏感因素（周期、利率、房产指数、行业事件）
- 持仓和交易操作

第一版不做详情弹窗也可以；先把卡片内迷你图做好。

### 3.6 响应式与可访问性

- 桌面端迷你图高度约 60–64px。
- 移动端高度约 48–52px，避免股票卡过高。
- 使用 `viewBox` 和百分比宽度，防止窄屏溢出。
- 红绿之外必须有箭头、正负号和文字，照顾色觉差异。
- 交易后的最新价端点要能实时更新，不要求整轮刷新。

### 3.7 显示层验收标准

- [x] 六只股票都显示折线图，不再只是裸折线。
- [x] 图上包含网格、昨收虚线、最新价圆点、最高/最低价。
- [x] 上涨为红色，下跌为绿色，并有 ▲/▼ 和正负号。
- [x] 股票模块有“红涨 · 绿跌”图例。
- [x] 净资产、现金流等非股票指标没有被误改成红涨绿跌。
- [x] 单点历史、平盘、极端价格（1/500）都不出现异常。
- [x] 顶部行情条与股票卡使用同一套颜色规则。
- [x] 桌面和移动端都不溢出、不遮挡。
- [x] P0 不改变服务器状态和交易规则。

## 4. 交易操作简化（P0.5，仍可只改前端）

- 数量快捷按钮：`1 / 5 / 最大`。
- 交易前显示：
  - 预计花费或到账
  - 手续费
  - 价格冲击
  - 交易后的现金余额
- 显示股息率和下次派息倒计时。
- 显示持仓占比、平均成本、当前盈亏。
- 对价格冲击使用与服务器一致的计算方式，并注明是“预计值”。

这些操作能明显减少“输入数量—提交—才发现买不起”的试错成本。

## 5. 规则与数值改动（建议，需单独确认）

### 5.1 六只股票的性格矩阵

不要增加股票数量，把现有六只做成不同资产：

| 股票 | 定位 | 建议波动 | 主要敏感因素 |
| --- | --- | --- | --- |
| 星海银行 | 防守、利率敏感 | 低 | 基准利率、贷款/抵押规模 |
| 城市地产 | 周期、房产 | 中 | 房产指数、利率、地产开发 |
| 新能集团 | 高波动资源 | 高 | 能源事件、未来产业开发 |
| NEO 科技 | 高波动成长 | 高 | AI 事件、科技园区开发 |
| 快乐食品 | 防守消费 | 低 | 衰退期相对抗跌、稳定股息 |
| PIXEL 娱乐 | 文旅情绪 | 中高 | 旅游、消费、事件行情 |

建议为每只股票增加配置：

- 波动率倍率
- 周期敏感度
- 利率敏感度
- 房产指数敏感度
- 行业事件暴露
- 股息率

股票元数据建议从 `server/engine.ts` 内联创建改为独立配置，便于测试和后续调整。

### 5.2 合理价值与均值回归

当前价格只有随机游走，建议增加一个缓慢回归的锚：

```text
合理价值 = 基础价
         × (1 + 行业周期系数)
         × (1 + 利率敏感系数 × (基准利率 - 0.03))
         × (1 + 房产指数敏感系数 × (房产指数 - 1))
         × (1 + 区域发展加成)

新价格 = clamp(
  旧价格 + 0.35 × (合理价值 - 旧价格)
  + 随机噪音
  + 全球事件冲击,
  1,
  500
)
```

设计约束：

- 价格仍然随机，不变成完全可预测的公式。
- 合理价值只做“锚”，不做硬性回归。
- 估值只展示区间判断，不直接显示精确公式。
- 区域发展加成要小且封顶，避免玩家通过自己升级地产无限抬升自己持有的股票。
- 优先使用全城区域发展指数，而不是单个玩家控制的资产。

### 5.3 每 5 轮财报与股息

当前股息只是自动打钱，没有行情反馈。建议把第 5、10、15……轮做成股市节奏点：

- 发放税后股息。
- 公布公司/行业财报。
- 根据盈利、城市发展、周期位置给股价一次向上或向下的跳空。
- 显示“财报超预期 / 不及预期”的简短提示。
- 在图表上标记财报轮次。

第一版可以只做“股息 + 价格向合理价值靠近”，不必引入完整的利润表。

### 5.4 连接城市发展

建议把股票和全城开发程度做弱关联：

- 星海银行：贷款、抵押、存款规模。
- 城市地产：房产指数、地产总等级。
- 新能集团：未来产业区发展。
- NEO 科技：科技园区发展和 AI 事件。
- 快乐食品 / PIXEL 娱乐：文旅、酒店、影院类地产发展。

这类联动只作为合理价值的小幅修正，并设置上限，避免股市变成地产的杠杆放大器。

### 5.5 事件与经济周期一致化

当前“事件随机 + 周期顺序推进”会产生语义冲突。建议让事件决定周期阶段：

| 全球事件 | 建议周期 |
| --- | --- |
| 经济繁荣 | 繁荣 |
| 金融危机 | 危机 |
| 房地产泡沫 | 过热 |
| 房地产调整 | 衰退 |
| AI 技术革命 | 繁荣 / 过热 |
| 能源危机 | 过热 |
| 央行降息 | 复苏 |

这样租金、工资、股价和界面描述才是一套连贯的世界状态。

**注意：这会改变租金和工资的周期系数，属于规则改动，不能和 P0 显示改版混在一起发布。**

### 5.6 “房地产调整”源码复核

2026-10-24 实施时核对 `marketTick`：

- 其他股票 × 0.96。
- 银行/地产股 × 0.8。
- 房产指数 × 0.7。

原方案将房价系数 0.7 误认为其他股票的系数。实际银行/地产股确实额外承压，现有文案与实现一致。本轮维持原有文案与数值；后续如重构规则，再按完整平衡测试评估。

### 5.7 AI 参与定价

当前机器人股票交易很少。建议增加简单估值规则：

- 价格明显低于合理价值：买入。
- 价格明显高于合理价值：卖出。
- 现金不足或持仓过多：不操作。
- 不做高频交易，不做未来信息读取。

这会让市场更活跃，但不会让 AI 变成主要对手。

## 6. 明确不做

本轮不建议加入：

- K 线 / 蜡烛图  
  当前服务器只有每轮收盘价，没有开盘、最高、最低数据；硬做会变成假 K 线。需要新增 OHLC 或 tick 历史才可以考虑。
- 做空
- 期权、融资融券、杠杆
- 订单簿、限价单、止损单
- 增加第七只或更多股票
- 让股票收益压过地产租金
