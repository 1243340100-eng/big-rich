# 棋盘周边城市群 · 城市碗方案

- 日期：2026-10-25
- 状态：已实现，参数校准与验收结果见《周边城市群_城市碗实施记录_20261025.md》
- 定位：**棋盘不是整座城市，而是城市里的一个街区**
- 方案：城市碗（方案 A）——低细节体块环绕，靠现有雾效收边
- 不改动：对局规则、地块归属、相机默认构图、棋盘本身几何

---

## 1. 结论先说

做，但**不做"无限延伸"**。

现有雾效是 `fog(sky, 65, 135)`（[SceneLighting.tsx:10](../src/scene/SceneLighting.tsx#L10)），135 之外全部被吞掉。城市群做到半径 90 就收尾，边缘自然消失在雾里——"无限"这个感觉是白送的，真建到 2 公里纯属浪费。

真正的收益不是"城市更大"，而是**尺度参照**：现在一块 22.8 × 22.8 的板漂在雾里，观众无法判断它有多大。四周有楼，立刻就知道了。

---

## 2. 定位变化带来的三个连带影响

棋盘从"悬空模型盘"变成"城市里的一个街区"，有三件事必须一起改，否则只加楼会露馅：

1. **必须补地面。** 现在板子之外什么都没有（[BoardBase](../src/Board.tsx#L2444) 是一块独立板）。只加楼不加地，看起来就是"一群楼也在飘"。
2. **必须补环街。** 板子外沿 11.4，城市从 15 起步，中间 3.6 的空隙要用道路/铺装连起来，否则棋盘像嵌在坑里。
3. **`ContactShadows` 要挪。** 它现在在 `y = -0.66`（[Board.tsx:3050](../src/Board.tsx#L3050)），是"悬空投影"的关键道具。加了地面后它会被埋进地下，要抬到地面上方，让它变成"广场在街道上的投影"。

> 这三条是这个方案里唯一的"身份改造"，请确认可接受再进 P0。

## 3. 空间结构

从中心向外五层：

| 层 | 半径 | 内容 | 作用 |
| --- | ---: | --- | --- |
| 广场 | 0 – 11.4 | 现有棋盘（不动） | 主体 |
| 环街 | 11.4 – 15.5 | 铺装、行道树、路口 | 把棋盘接到城市 |
| 近带 A | 15.5 – 26 | 3–9 高，6–14 宽，坡顶/平顶混合 | 街区肌理，解决"空" |
| 中带 B | 26 – 38 | 6–14 高，10–20 宽 | 纵深，远处层层叠叠 |
| 远带 C | 55 – 90 | 14–30 高，纯剪影 | 只在拉远时出现的天际线 |

38–55 之间**刻意留低**（公园、水岸、铁路场站一类的低矮带）。这不是省事——见 §4.2，这一段在默认镜头下正好是画面顶边，放高楼会顶出画面、抢走棋盘的焦点。

## 4. 两条硬约束（决定所有高度）

### 4.1 不遮挡：近侧楼不能挡住棋盘

默认相机距离由 `max(42, 15.2 / sin(19°))` 算出约 **46.7**，位置约 `(24.2, 26.3, 29.3)`，俯角 **34.7°**，水平距中心 **38.0**。

棋盘近边在 `r = 11.4`、高度约 `0.02`。相机到该点的视线，在半径 `r` 处的高度是：

```
视线高度(r) ≈ 0.99 × (r − 11.4)
```

取 10% 余量，得到生成时必须夹紧的规则：

```
h(r) ≤ 0.9 × (r − 11.4)
```

因为相机是 360° 可环绕的，所以按**最坏方位（近侧）**统一夹紧，不区分朝向——这样玩家怎么转都不会突然被楼挡住。

| r | 允许最大高度 |
| ---: | ---: |
| 15.5 | 3.7 |
| 20 | 7.7 |
| 26 | 13.1 |
| 38 | 23.9 |

### 4.2 不抢戏：远侧楼不能顶出画面

同一套相机参数下，垂直半视角 19°、俯角 34.7°，画面顶边在**地平线下 15.7°**。远处的楼越高越往画面上方顶；到 `r ≈ 45` 时，任何超过 3 的楼都会顶出画面。

这带来一个反直觉的结论：**远带的高楼在默认视角下没有意义**——它们不是"背景"，而是会把画面上半部塞满的墙。

所以方案里：

- 38–55 留低，保证默认视角下画面顶边是天空和雾；
- 55–90 的塔群是**给拉远准备的**（`maxDistance = 140`，[Board.tsx:2957](../src/Board.tsx#L2957)）。玩家拉远时看到的整座城市，是"拉远"这个动作的奖励。

## 6. 生成规则（必须确定性）

**禁止 `Math.random()`。** 城市群必须每次刷新都一样，否则会破坏"这是同一座城"的记忆感，也会让截图对比失效。

复用现有的 `hash(seed, salt)`（[Board.tsx:75](../src/Board.tsx#L75)），按格子索引取值：

```ts
for each candidate (i, j) on a 40×40 grid in [-90, 90]:
  r = hypot(cx, cz)
  if r < 15.5 or r > 90: continue
  if r > 38 and r < 55: continue          // 低矮豁口
  band = r < 26 ? 'near' : r < 38 ? 'mid' : 'far'
  if hash(i * 131 + j * 17, 1) > density(band): continue
  h = lerp(minH, maxH, hash(i, j, 2)) * heightScale(band)
  h = min(h, allowedHeight(r))             // §4.1 的夹紧，硬性
  w = lerp(minW, maxW, hash(i, j, 3))
  d = w * lerp(.7, 1.3, hash(i, j, 4))
  rot = band === 'far' ? hash(i, j, 5) * Math.PI : Math.floor(hash(i, j, 5) * 4) * Math.PI / 2
```

`allowedHeight(r)` 单独一个函数，方便以后接"玩家放大到某处时局部生成"。

## 7. 技术实现

### 7.1 组件

新增 `src/scene/distantCity.ts`（几何生成）+ `src/scene/DistantCity.tsx`（渲染），在 `Scene` 里挂在 `<BoardBase />` 之前：

```tsx
<SceneLighting />
<DistantCity />      {/* 新增：地面 + 城市群，最先画 */}
<BoardBase />
...
```

### 7.2 绘制调用

- **城市体块**：1 个 `InstancedMesh`（BoxGeometry）+ 逐实例 `setColorAt`。
- **坡屋顶**：1 个 `InstancedMesh`（四棱锥），只服务近带约 42 栋。
- **地面**：1 个 CircleGeometry（半径 120）。
- **环街铺装**：1 个 RingGeometry（11.4 – 15.5）。

合计 **+4 个绘制调用**，对照现有 176 个合并网格基本无感。

### 7.3 必须设的属性

```tsx
<instancedMesh
  args={[geometry, undefined, count]}
  frustumCulled={false}      // 包围球半径 180，永远在视锥内，省掉每帧判定
  raycast={noRaycast}        // 不能挡住棋盘的点击
  castShadow={false}         // 阴影相机只有 ±20，远处标了也没用
  receiveShadow={false}
/>
```

`raycast={noRaycast}` 不是优化，是**必须**——否则点击外面的楼会中断棋盘交互。

### 7.4 时间变化

不加新光源，直接吃现有 `ambientLight` / `hemisphereLight` / 三盏方向光，颜色随 `timeOfDay` 自然变化。雾色跟着 `p.sky` 走，城市边缘会自动融进天空，不用额外处理。

### 7.5 地面高度与现有元素的冲突

| 元素 | 现在 | 需要改成 |
| --- | --- | --- |
| 城市地面 | 无 | `y = -0.30`，半径 120 |
| 棋盘板底 | `-0.64` | 不变（埋进地下 0.34，露出 0.34 的台基，保留一点"广场是件东西"的感觉） |
| `ContactShadows` | `y = -0.66` | `y = -0.29`，`scale` 38 → 30，透明度下调 |
| 环街 | 无 | 与地面同高，`y = -0.30` |

城市群预算：

| 项 | 预算 | 说明 |

## 10. 风险与回退

| 风险 | 表现 | 处理 |
| --- | --- | --- |
| 抢焦点 | 城市比棋盘更吸引眼球 | 降近带高度、把城市饱和度压到 0.85、加强雾 |
| 缝隙感 | 棋盘和城市之间有"坑" | 环街铺装必须做，不能省 |
| 视觉噪音 | 220 个色块太花 | 配色收敛到街区色 ±8% 明度，禁止高饱和 |
| 未来产业区错位 | 城市配色和四大街区不匹配 | 按方位角划四个象限，各用本街区色 |
| 性能 | 罕见设备掉帧 | 一键关停：`CITY.enabled = false`，组件整体返回 `null` |

回退成本极低：全部逻辑集中在 `distantCity.ts` + 一个 `<DistantCity />`，删掉两处引用即恢复现状。

## 11. 待确认

1. **地面高度**：`y = -0.30`（保留 0.34 台基，广场仍像"一件东西"）还是 `y = -0.08`（完全嵌平，彻底去掉悬浮感）？我倾向前者。
2. **38–55 的低矮豁口**放什么：公园绿地 / 河道 / 铁路场站？我倾向河道——一条环城水系能同时解释"这里为什么没有楼"和"城市为什么分内外两环"。
3. **远带 C 要不要做**：它是纯为拉远服务的。如果玩家基本不拉远，P2 可以砍掉，省 90 个实例和一整套调参。


## 12. 实施结果

已完成 P0–P2，以及 P3 的材质亮窗、屋顶压线与两处低矮设备版本。采用 `y=-0.30`、环城水系和拉远可见的远带；默认镜头仍为原位置与 38° 视场。为满足宽景完整性和无地面边缘的验收目标，最大拉远时视场渐扩到 82°，承托地面半径调至 220，楼群仍止于 90。城市层为 220 栋、42 座坡屋顶、3,188 三角面、4 次绘制。完整校准说明、验证证据与文件位置见 [实施记录](周边城市群_城市碗实施记录_20261025.md)。
