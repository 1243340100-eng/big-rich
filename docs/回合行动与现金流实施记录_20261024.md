# 回合行动与现金流实施记录

日期：2026-10-24。依据《回合行动与现金流体验改进方案》，采用方案推荐取舍实施 P0–P3。

## 交付内容

- `src/game/primaryAction.ts` 统一计算主行动：开局、掷骰、买入、升级、结束、竞拍、补现金、排名与等待。等待状态没有不可用的假按钮。打开抽屉或弹窗时，底部主按钮弱化。
- 买入预览包含价格、当次租金、买后现金与固定支出增量；买入成功以服务器归属更新为准，自动选中地块。管理阶段选中可升级自有地块时，主行动变为升级；满级、抵押或无选中上下文时显示结束回合。现金不足保留升级预览并说明原因。
- 地块弹窗与地产抽屉共用升级权限、费用、当前经济周期租金、现金与维护预览。租金统一标为“万/次”，升级仍复用原有脚手架和幕布施工动画。
- 更多操作保留城市概况、地产、股票、银行、交易、会客厅、指南和房主设置；原有右侧抽屉继续可用。
- 现金流摘要常驻行动条。仪表盘包含存款、股票市值及单次可售净额、抵押额度、信用贷款、竞拍预留、固定支出及保守现金跑道。抵押额度排除拍卖和未完成提案涉及的地产。
- 急救面板按当前估算代价率动态排序：取款、卖股、贷款、抵押、售房；重组固定在末尾，单独确认。每项显示执行后现金及支出，允许部分补足；确认后只发一个 action，等待服务器重新计算，不自动结束回合。行情版本变化会撤销原确认有效性。
- 股票筹资复用现有精确成交预览，包含手续费、税、滑点和 1000 股单次上限。贷款、抵押、出售及卖股后的支出估算考虑信用变化；卖股同时考虑剩余持仓报价变化。重组预览包含清算后的剩余债务。
- `shared/finance.ts` 提供服务端与前端共用的结算公式，保留既有取整顺序；存款利息计入存款，不冲抵现金支出。
- 服务端在每个个人回合开始写入可选 `lastSettlement`，记录真实利息、税、维护、存款利息、净变化和唯一回执编号。旧存档缺字段时保留缺省，界面只展示原 `lastFlow`，不补造历史明细。回执不会在重连时重复播放。
- 租金日志增加可选结构化收据，区分付款总额与收款方扣税后收入，避免工资和租金同次发生时误用现金差额。
- 增加买入、升级、收租、重组提示和现金数字过渡；回合开始显示非阻塞结算回执。音效为原创 Web Audio 合成音，默认静音，用户手势启用，提供独立静音和音量。减少动态效果同时应用于界面、城市装饰与升级动画，并遵循系统设置。
- 新弹窗支持 Escape、焦点圈定和关闭后恢复；关闭的抽屉使用 inert 防止键盘误入。主按钮高度 46px。

## 取舍与边界

- 采用推荐的“下一步建议 + 逐项预览确认”。没有新增一次确认多步的批量接口，也没有前端连续发请求模拟原子操作。
- 排序比较一个个人回合的增量支出、赎回费、即期交易损失，计入出售后的固定支出节省，并用一次税后租金机会损失作比较假设。它是公开口径的游戏内估算，不保证未来租金或股价。
- 股票净额是每只至多 1000 股的单笔估算，不能当作一次卖光全部持仓的保证金额。
- 财务扣费时机仍为个人回合开始。工资、市场、租金、AI、房间和存档主规则保持原有时序。
- 已生成 `dist`。已经运行且不热重载的服务，需要正常重启后加载新的结算字段与租金收据；旧服务连接期间，页面使用已有汇总数据降级展示。没有强制停止原来的 3001 服务。
